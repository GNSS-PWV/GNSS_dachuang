## 1. 问题定义

二阶段 ProfileTransformer 的输入是**探空垂直廓线 [ELV, TS, PS, WPS]**。真实 GNSS 部署时站点**没有探空廓线**，只有 GNSS 观测的 ZWD（锚点）。因此需要"传统模型"（一阶段 GRU，预测地表 Ps/Ts/WPS/Tm）作为输入基础：
- 用一阶段预测的地表温压替换/订正（气候态）廓线 → 喂给二阶段 → PWV。

对比口径（同一批 2017 样本）：
| 口径 | 含义 | 是否有真实温度气压 |
|---|---|---|
| real | 真实探空廓线 | ✅ 有（oracle 上界） |
| real_surf_p1 | 真实廓线，地表 TS/PS/WPS 用一阶段预测替换 | ❌ 无 |
| clim | 纯气候态平均廓线（现有部署模拟） | ❌ 无 |
| clim_surf_p1 | 气候态廓线 + 地表用一阶段预测替换 | ❌ 无（改进①） |
| clim_adj_p1 | 气候态廓线整体订正到一阶段预测地表值 | ❌ 无（改进②） |
| gpt3 | GPT3 经验 Tm 基线 | ❌ 无 |

## 4. 结论（可写进论文/汇报）

1. **oracle 场景**：真实廓线时，地表温压换成一阶段预测，PWV 仅退化 **+11%**（0.076→0.084）——二阶段对地表温压误差不敏感（廓线信息主导）。
2. **无真实数据部署**：纯气候态廓线 2.16 mm → 一阶段订正后 **0.33–0.39 mm（降 ~85%）**，**追平 GPT3（0.31）且偏差更小**（clim_adj_p1 +0.081 vs GPT3 −0.161）。
3. **"传统模型直接映射到新模型"成立**：一阶段预测的地表温压是部署时最有价值的"传统模型先验"，把二阶段从"不可用（2mm+）"拉到"可用（0.33mm，GPT3 水平）"。
4. **剩余差距**：0.33 vs oracle 0.076（约 4.4×），来源是气候态廓线本身与真实廓线的差异（上层结构信息缺失）——可通过"部署鲁棒性微调"（已提交任务 2238349）进一步压缩。
