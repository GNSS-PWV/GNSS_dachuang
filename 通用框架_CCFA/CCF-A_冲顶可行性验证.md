# CCF-A 冲顶可行性验证文档（通用非均匀地理时序框架）

> 状态：**首轮冷启动验证完成（2026-08-16）；多 seed 复核待做**　|　决策逻辑：通用性验证通过 → 投入冲 CCF A；不通过 → 回到 PWV 论文线（RSE/ACP）
> 一句话：把 GNSS 水汽廓线反演的方法论抽象成"通用非均匀地理时序预测算法"，先在公开多站点 PM2.5 数据上验证"未见站零样本泛化 + 物理锚点重参数化"是否跑赢常见基线。

## 0. TL;DR

- 已选定并下载第一个通用基准：**Mendeley「Air quality dataset」DOI 10.17632/p86hnykz3d.2**（斯洛文尼亚 21 个空气质量站，2024-05 至 2025-12，逐小时 PM10/PM2.5+气象协变量，每站 14,100 条）。
- 站点经纬度/海拔已从 **ARSO 官方 XML 接口**拿到，全部 21 站匹配成功 → 具备"连续空间坐标嵌入"条件。
- 实验协议：**站点级留出（unseen-station）泛化**——14 训练 / 3 验证 / 4 测试站，完全模拟 PWV 场景（探空站训练 → GNSS 站零样本部署）。
- **初步结论（诚实版）**：
  1. **物理锚点重参数化 = 跨站泛化的决定性组件**（纯 GRU 未见站 RMSE 15.5 → +气候态锚点 6.8@1h / 9.6@24h）；
  2. **24h 前向预测：锚点框架击败 ridge 与 persistence**（9.63 vs 10.54 / 12.05，R² 0.635）——长时程下框架优势成立；
  3. **1h 前向：persistence 仍最强**（小时级自相关太强，模型无法超越）——1h 不是框架的菜；
  4. **空间索引支柱未显示增益**（锚点模型加坐标后无提升甚至略降）——需冷启动协议/更大站点网络重新检验（正在补做）。
- 当前可行性判定：**部分成立**。物理锚点支柱强迁移、可在预报时程击败基线；空间索引支柱仍需更合适协议验证。

## 1. 为什么做这件事（背景与决策树）

当前 PWV 论文线已具备：第二阶段 ProfileTransformer（官方 36 站 RMSE 0.0653→0.0609 mm，较 GPT3 提升 ~82%）、GNSS 泛化验证、消融、层贡献、极端个例、部署模拟等，可投 **RSE / ACP**。

若冲 **CCF A / 顶刊**，现有工作被质疑的点：
1. 场景绑定过死；2. 数据集单一；3. 创新增量太小；4. 评审错位。

对策：抽象通用算法 + 3 套以上公开基准 SOTA 对比 + 理论（收敛性/复杂度下界）+ 叙事重构（70% 通用 / 30% PWV 落地）。

**本阶段 = 决策点**：先在公开多站点数据上验证方法论是否"通用且能打"。

## 2. 方法论抽象：三支柱（PWV → 通用）

| PWV（ProfileTransformer） | 通用抽象 | PM2.5 落地实例 |
|---|---|---|
| 连续高度/气压层索引 + 正弦 PE | **连续空间索引嵌入**：(lon,lat,elev) 多频正弦 PE | 未见站零样本部署（无离散 ID 表） |
| 站点气象参数全局条件 | **全局/上下文条件**：时间上下文 + 最近观测逐时条件化 | 小时/季节 + 24h 气象历史 |
| PWV = Pi × ZWD（观测锚点） | **物理锚点重参数化**：y = anchor × exp(g) | anchor = (小时,月)气候态（预报）或实测 PM10（nowcast） |

## 3. 数据集（第一基准）

- Mendeley Data，DOI `10.17632/p86hnykz3d.2`（CC-BY-4.0），zip 2.98MB，21 站 CSV。
- 变量：datetime / PM10 / PM2.5 / temperature / rain / pressure / precipitation / wind_speed / clouds / wind_direction（49% 缺失）。
- 缺失：PM2.5 ~1.65%，先线性插值+前后填充；wind_direction 独热（8 方位+缺失）。
- 站点坐标：ARSO 官方 XML（`arso.gov.si/xml/zrak/ones_zrak_urni_podatki_zadnji.xml`），46.0–46.6°N、13.6–16.2°E、海拔 56–574 m，非均匀分布。
- PM2.5：mean 13.2 µg/m³，std 13.7，min 2，max 384。
- 本地：`通用框架_CCFA/data/`（extracted / stations_meta.csv / prepared.pkl）。

## 4. 实验协议

### 4.1 主协议：站点级留出（unseen-station generalization）
- 21 站随机划分（seed=42）：**14 训练 / 3 验证 / 4 测试**（测试：E802、E404、E418、E412）。
- 预测任务：给定过去 24h 观测（PM10/PM2.5 历史/气象/时间特征），预测 t+H 时刻 PM2.5（H=1/6/24h）。
- 锚点：`clim_*` 用训练站 (小时,月) 气候态（预报模式）；`pm10_*` 用目标时刻实测 PM10（仅 nowcast 语义）。
- 评估：聚合 RMSE/MAE/R² + 逐站 RMSE 均值。

### 4.2 冷启动协议（隔离"空间索引"支柱，补做中）
- 输入仅：连续坐标 PE + 时间特征（+ 气候态锚点）。**无本地历史、无本地气象**——纯"新地点零样本"。
- 若空间模型显著优于无空间模型与 ridge+坐标 → 空间索引支柱成立。

## 5. 模型与基线

| 名称 | 空间嵌入 | 锚点 | 说明 |
|---|---|---|---|
| persistence | - | - | ŷ(t+H)=y(t-1)，短时程强、长时程失效 |
| climatology | - | - | 训练站 (小时,月) 均值 |
| global_mean | - | - | 训练站全局均值 |
| ridge | - | - | 展平 24×27 窗口线性回归（alpha 验证站调） |
| gru_plain | ✗ | none | 纯 GRU（常见时序 SOTA 基线） |
| gru_anchor_clim | ✗ | clim_mul | 只加锚点（验证锚点贡献） |
| gru_spatial | ✓ | none | 只加空间索引（验证空间贡献） |
| ours_clim_add | ✓ | clim_add | 空间+加性锚点 |
| **ours_clim_mul** | ✓ | clim_mul | **空间+乘性气候态锚点（主推）** |
| ours_pm10_mul | ✓ | pm10_mul | 空间+实测 PM10 锚点（nowcast 类比 Pi×ZWD） |

超参：GRU hidden=64, layers=2, Adam lr=1e-3, batch=512, epoch≤100, 早停 patience=12（验证站 RMSE），head 零初始化。

### 6.4 解读（诚实版）
1. **物理锚点 = 跨站泛化的关键**：纯 GRU 在未见站 R²≈0.05（几乎等于预测全局均值）；只加气候态锚点后 R² 0.82@1h / 0.64@24h。这直接对应 PWV 里"Pi×ZWD 用观测锚点兜底"的设计，跨域可迁移。
2. **长时程（24h）框架胜出**：gru_anchor_clim 9.63 < ridge 10.54（+9%）< persistence 12.05（+20%）。气象协变量+气候态先验在 persistence 失效时体现价值。
3. **短时程（1h）persistence 不可超越**：小时级自相关太强；该协议只作完整性展示。
4. **空间索引未显示增益**：加坐标 PE 后 ours_clim_mul ≈ gru_anchor_clim（1h 6.95 vs 6.82；24h 10.24 vs 9.63）。可能原因：① 14 训练站太少，学不出"地理→污染水平"映射；② 测试站自带 24h 本地历史，空间信息被冗余覆盖；③ PE 参数未调。→ 用冷启动协议（无本地历史）检验，见 §7。
5. **空间索引单独（无锚点）无效**：gru_spatial 16.1≈gru_plain，说明纯地理嵌入无法替代"锚点+历史"提供的信息量。

## 10. 2026-08-16 更新：冷启动首轮验证完成

### 10.1 执行与公平性修正
- 完成 `src/cold_start.py --seed 42 --epochs 80`；结果保存于 `results/coldstart_seed42/summary.json`。
- 针对本机无页面文件导致的 Ridge 内存失败，Ridge 基线改为 `float32 + solver="lsqr"`，避免改变实验协议。
- 修正 `GeoIndexGRU` 的数值限幅：仅对乘性锚点的指数项限幅；直接回归 (`anchor="none"`) 不再被错误限制在 `[-12, 12]`，使无锚点基线可预测 PM2.5 的完整数值范围。

### 10.2 冷启动结果（seed=42，未见站 E802/E404/E418/E412）

| 模型 | RMSE | MAE | R² | siteRMSE |
|---|---:|---:|---:|---:|
| **mlp_plain（无空间、无锚点）** | **12.910** | **7.043** | **0.345** | **12.514** |
| mlp_clim（无空间+气候态） | 13.042 | 7.317 | 0.331 | 12.684 |
| mlp_spatial（空间索引、无锚点） | 13.100 | 7.143 | 0.325 | 12.635 |
| mlp_spatial_clim（空间索引+气候态） | 13.561 | 7.525 | 0.277 | 13.109 |
| climatology | 13.346 | 7.495 | 0.300 | 13.011 |
| ridge+coords | 14.066 | 8.002 | 0.222 | 13.845 |
| global_mean | 16.047 | 9.492 | −0.012 | 15.822 |

### 10.3 当前结论与决策
1. **空间索引支柱在该冷启动协议首轮不成立**：加入连续坐标 PE 后，RMSE 从 12.910 升至 13.100；与气候态锚点组合后进一步升至 13.561，未见站零样本泛化没有显示增益。
2. **物理锚点的价值仍由主协议支持**：此前 H=6/24h 的时序协议中，气候态锚点显著改善跨站泛化；但在“仅坐标+时间”的严格冷启动设定下，锚点本身不足以恢复站点差异。
3. **CCF-A 冲顶目前不应扩大投入**：单一 21 站基准尚未形成“空间索引+锚点”两个核心支柱都成立的证据。先补 1–2 个 seed；若结论仍为无空间增益，则回到 PWV 论文线（RSE/ACP），或在更大、空间覆盖更广的站点网络上重构该支柱后再评估。

### 10.4 后续最小验证
- 以 1–2 个不同 seed 重跑相同冷启动协议，报告均值与标准差；仅串行运行，避免 RTX 4060 8GB 的显存竞争。
- 若空间模型仍未优于 `mlp_plain` 与 `ridge+coords`，将该结果作为负结论归档，不再以此原型申报 CCF-A。
