# Phase-one causal feature version

This directory contains the isolated feature contract for the next phase-one
retraining. It does not overwrite historical scripts or checkpoints.

## Contract

- The prediction target is retained only as the label.
- Current `PS`, `WPS`, `TS`, and `Tm` are not input features.
- Dynamic features use lags `1, 2, 3, 6, 12` within `station_id + ELV`.
- Differences use lagged values only.
- Rolling means and standard deviations shift by one row before rolling.
- Static coordinates, height, and deterministic calendar features are allowed.
- Scaling statistics must be fitted on the training split only by the future
  training launcher.

Run the audit from this directory:

```powershell
python audit_phase1_feature_leakage.py --output audit_phase1_feature_leakage_20260829.json
```

The JSON report has two separate meanings: historical findings identify the
source of the old optimistic metrics, while the synthetic mutation checks
verify that the new feature implementation is causal at the target timestamp.

## Training prerequisite

Before retraining, the existing GRU launchers must be adapted to import
`build_causal_features` or `make_causal_sequences`. A checkpoint produced by
the old feature list must not be described as a causal-feature result.
